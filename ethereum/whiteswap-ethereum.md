## Architecture and execution map

- Factory and pair proxies use EIP-1967 slots and delegate to logic contracts. Factory `createPair` sorts tokens, deploys `WSProxyPair` with CREATE2, asks its controller for current pair logic and admin, initializes the proxy, then initializes the pair's factory/token state and records both lookup directions. The factory also controls `feeTo` and `feeToSetter`.
- Pair LP ERC-20 state, token addresses, reserves, cumulative prices, `kLast`, initialization flag and reentrancy lock live in proxy storage. Public value transitions are `mint`, `burn`, `swap`, `swapDiscount`, `skim`, and `sync`. Mint/burn are lock-protected; mint derives deposits from observed balance deltas, while burn pays pro rata from pair-held LP and current balances.
- `swap` transfers outputs optimistically, optionally calls `wbCall`, measures both balances and inferred input, checks the fee-adjusted constant-product invariant, and updates reserves and cumulative prices. The active verified pair applies `30 / 10,000` fee units, equivalent to the router quote's `3 / 1,000` fee. The standard router moves intermediate hop output directly to the next pair and supports exact-input/output, native-token and fee-on-transfer flows.
- Fee accounting follows the V2 `kLast` protocol-fee design: when `feeTo` is nonzero, mint/burn may mint protocol LP shares from growth in `sqrt(reserve0 * reserve1)`; disabling fees clears nonzero `kLast`. There is no separate token-denominated fee balance. Pair token balances are reserves plus any unaccounted donations until `sync`, `skim`, mint or burn resolves them.

## Entry points and invariants reviewed

- Factory pair creation, duplicate/sort checks, `feeTo` and setter transitions, proxy implementation/admin pointers, and controller-selected implementation for new pairs.
- Pair initialization, LP token transfer/permit, mint, burn, ordinary swap, discount swap, callback behavior, `skim`, `sync`, reserve bounds, timestamp/cumulative-price transitions, and `kLast` fee minting.
- Current router liquidity and swap entry points, fee-on-transfer routes, multihop settlement, quote math, CREATE2 address derivation, WETH wrap/unwrap and minimum-output checks.
- Invariants: each completed pair update stores actual token balances as reserves; mint shares use balance deltas and current supply after protocol fee minting; burn entitlements use pair-held LP over current supply and actual balances; swap settlement meets the same fee-adjusted product inequality as router quotes; callbacks run under the pair lock and failed settlement reverts output and state changes; cumulative prices accrue using prior reserves over elapsed time.

## Findings

No confirmed implementation defect was identified in the sampled active WhiteSwap proxy family.

### Rejected hypotheses

- **Router quote fee differs from pair settlement:** router quote math uses the canonical `997/1000` input factor. Active pair logic uses `(balance * 10,000) - input * 30`, which is the same 0.3% fee basis, and the same adjusted balances are checked against `reserve0 * reserve1 * 10,000^2`. The observed code paths are consistent.
- **`swapDiscount` permits callers to choose a zero fee:** the pair's internal `_swap` permits a nonzero discount only when `msg.sender` equals the hard-coded legacy router proxy `0x463672...`; direct users cannot satisfy that condition. At the review snapshot, that address is itself a proxy, but its active verified router source does not call `swapDiscount`; neither does the currently documented router. No public discount route or caller-controlled reduction was established. Discount values above 30 revert through checked SafeMath subtraction.
- **Upgradeable pair proxy points to unreviewed logic:** the sampled pair EIP-1967 implementation slot and controller `pairLogic()` both resolve to verified `WSPair` logic `0x5248...`. This does not guarantee future configuration; conclusions apply to the observed pointer and source.
- **Router pair address calculation points elsewhere:** independently computing CREATE2 from the factory, sorted USDC/WETH addresses, and the verified router init-code hash produces the sampled pool address `0xac3b...` exactly.
- **Donations are immediately skim-able:** `skim` transfers only balance excess over stored reserves, while `sync` adopts balances; this is the conventional, documented V2 behavior, not a reserve-accounting defect.

## Validation and limitations

- No local regression was written because no credible invariant violation remained. Read-only calls were used for sample `factory`, tokens, reserves, proxy implementation slots, controller pair logic, factory fee state, router factory/WETH, and pair count. No state-changing calls were made to public contracts.
- No claim is made that every WhiteSwap pool, token, staking/reward contract, or future proxy implementation was reviewed. The sampled active factory currently reports `feeTo == 0`, `allPairsLength == 21`; these are snapshot values. The historical repository and audit are not represented as exact deployed-source matches where the current verified logic contains later code.
